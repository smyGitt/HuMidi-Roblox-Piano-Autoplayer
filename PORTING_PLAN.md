# HuMidi Rust/Tauri Porting Plan

Source of truth for the Python original: `../piano-midi-autoplayer`. This document is binding per `CLAUDE.md`'s regression-test-parity rule: a Python module is not considered ported until its mirrored Rust test module exists and passes.

## Porting order (not yet executed beyond scaffolding)

`core/models.rs` (done) -> `core/config.rs` (done, consumer keys only) -> `core/midi.rs` (done -- `TempoMap`/`KeyMapper`/`MidiParser` via `midly`) -> `core/keyboard_driver.rs` (done -- `enigo` + the platform-specific fixes documented in `docs/core/keyboard_driver.md`) -> `core/humanizer.rs` (done -- see `docs/core/humanizer.md`) -> `core/section_analyzer.rs` (done -- see `docs/core/section_analyzer.md`) -> `core/compiler.rs` (done -- see `docs/core/compiler.md`) -> `core/pedal/mod.rs` (done -- strategy dispatch: adaptive/harmonic/rhythmic/AI; the BiLSTM model itself in `core/pedal/model.rs` was already implemented and verified in an earlier session; see `docs/core/pedal/mod.md`) -> `core/player.rs` (done, decision logic only -- see `docs/core/player.md`) -> `managers/*` (done -- `config_manager.rs` fully done, `hotkey_manager.rs` now includes the real OS hook adapter too, `update_manager.rs` partially done pending real update infra; see their docs) -> `core/session_cache.rs` (done -- see `docs/core/session_cache.md`) -> `core/translator.rs` (done -- see `docs/core/translator.md`) -> `controllers/*` as Tauri commands/events, including the real playback-thread and hotkey-hook integration layer (**done -- see "Controllers: what's done and what's left" below for the remaining, deliberately out-of-scope slice**) -> the real React UI build-out (still not started; the `run_pedal_smoketest` scaffolding button is still the only frontend-visible thing).

## Controllers: what's done and what's left

`controllers/*` (2115 lines across 7 Python files) splits into three genuinely different categories, not one uniform porting task:

1. **Pure/portable logic:** `controllers/app_state.py` (see `docs/state.md` for which fields), `controllers/midi_parse_worker.py` (collapses into a single `parse_midi_structure` command, see `docs/commands.md`), and the non-Qt-coupled free functions from `controllers/PlaybackController.py` (`_extract_pedal_intervals`, `_apply_hand_assignment`, `_prepare_notes`). **Done.**
2. **Real integration work -- done, tracked here for what it actually built:** `PlaybackController`'s two-phase compile pipeline as real Tauri commands (`compile_notes`/`compile_pedal`/`compile_pedal_and_play`), backed by `core::session_cache` (now a complete port, not a stub) for the cache-invalidation logic those workers depended on. `core::player::PlaybackEngine` is now driven on a real background thread by `commands::run_playback_loop`, with `PlayerEvent -> app.emit(...)` dispatch and `start_playback`/`toggle_pause`/`stop_playback`/`seek_playback` as real Tauri commands. `managers::hotkey_manager::HotkeyManager` is now wired to a real global keyboard hook via the `rdev` crate (`commands::spawn_hotkey_listener`, `managers::hotkey_manager::rdev_key_to_raw`) -- see `docs/managers/hotkey_manager.md` for why `rdev` rather than `tauri-plugin-global-shortcut`. The save flow (`_SaveWorker` -> `commands::save_playback`; `load_coordinator.py`'s `_validate_save_data`/`_write_json_atomic` -> `commands::validate_save_data`/`core::atomic_write::write_json_atomic`) is ported. See `docs/commands.md` for the full command list and design notes.
3. **Out of scope for `src-tauri` entirely, not a gap:** `controllers/load_coordinator.py`'s UI-facing dialog/widget glue, `controllers/playback_ui_coordinator.py`, `controllers/settings_coordinator.py`, `controllers/translator_coordinator.py`. All are PySide6 GUI-coordinator code -- confirmed by reading them, not assumed -- tightly bound to specific widget types (`QMessageBox`, `QFileDialog`, `ui.dialogs.TrackSelectionDialog`, button `.clicked.connect(...)` wiring) that have no meaning in a Rust backend. Same category as the already-excluded Qt-widget test files (`test_color_swatch.py` etc., see below): the logic belongs entirely to the future React UI.

**Real gaps still remaining, not covered by the above:** `managers::update_manager::check_for_updates` remains `todo!()` (infra-blocked, not a logic gap). **Resolved since this was written:** `managers::config_manager::ConfigManager` is now instantiated in `AppState` (`AppState::default()` constructs and `.load()`s it at startup) and backs `get_save_dir`/`set_save_dir`/`get_midi_dir`/`set_midi_dir`, with real persistence to `~/.humidi/config.json` -- see `docs/commands.md`. The React frontend has also long since been built out past the `run_pedal_smoketest` scaffolding (6 tabs, all reachable) -- this line is stale and kept only as a historical marker of this document's age; see `docs/CODEBASE_REFERENCE.md` for actual current frontend state.

**Known Python bugs to fix, not carry over:**
- `TempoMap.has_explicit_time_signatures` only checks the numerator, mis-detecting 4/2 and 4/8 as default 4/4.
- `transpose` config key is currently non-functional/dead in the Python source.

## Platform target

Windows, macOS, Linux X11, Linux Wayland -- Tauri's default-supported set. `core/keyboard_driver.rs` is the module with the most real platform-specific behavior; see its doc for details, including a known macOS-specific `pynput` bug history that must inform (not just inspire caution about) the `enigo` port.

## Verified so far (do not re-verify, re-derive, or second-guess without new evidence)

- BiLSTM pedal model: numeric parity confirmed against the real PyTorch checkpoint, max abs diff 2.98e-7. See `src-tauri/tests/pedal_parity.rs` and `docs/core/pedal/model.md`.
- Full toolchain (native Windows Rust, Node, MSVC, Tauri v2, WebView2) builds and runs on this machine.
- `core/models.rs` is a complete, tested port of `core/models.py`.
- `core/midi.rs` is a complete, tested port of `core/core.py` (`get_time_groups`, `TempoMap`, `GlobalTickMap`, `MidiParser`, `KeyMapper`), 48 tests passing. One documented Python bug fixed, not carried over (`has_explicit_time_signatures` denominator check). See `docs/core/midi.md`.
- `core/keyboard_driver.rs` is a complete, tested port of `core/keyboard_driver.py` (`KeyboardDriver` trait, `EnigoDriver`, `pressed()` scoped-modifier-hold guard, macOS digit remap, macOS accessibility gating), 33 tests passing. One deliberate deviation, backed by reading `enigo` 0.6.1's own source (not guessed): the Linux X11 keysym-forcing workaround (`_LinuxController` in Python) was NOT ported, because `enigo`'s `x11rb` backend unconditionally uses `XTest.fake_input()` for every key already -- see `docs/core/keyboard_driver.md` for the exact source citations. Linux Wayland is still unsupported (no Wayland/libei feature enabled in `Cargo.toml` yet, still gated as of 0.6.1). Real OS key-injection is unverified on every platform (Windows included) -- only the pure coercion/decision logic was unit-tested; that was always going to require live sessions per the "Verification bar" in the doc. **Corrected while porting `core::player`:** `press`/`release` now return `Result<(), KeyActionError>` instead of panicking -- reading `player.py` in full revealed `Player._execute_chord_event` catches per-call physical-input failures and keeps playing rather than crashing, which the original panic-on-failure design contradicted. See the "Correction" section in `docs/core/keyboard_driver.md`.
- `core/humanizer.rs` is a complete, tested port of `core/humanizer.py` (`Humanizer::apply_to_hand`, `Humanizer::apply_tempo_rubato`), 34 tests passing. Added `rand = "0.9"` as a direct dependency (already resolved transitively via `candle-core`, now explicit) for Gaussian/uniform sampling; RNG is distributionally equivalent to Python's, not bit-for-bit (no test in the Python source required bit-for-bit parity -- see `docs/core/humanizer.md`). Also added `core::midi::get_time_group_indices`/`_with_threshold` (8 new tests in `midi.rs`) to support in-place note mutation, since the existing `get_time_groups` returns clones.
- `core/section_analyzer.rs` is a complete, tested port of `core/section_analyzer.py` (`assign_hands`, `SectionAnalyzer`), 37 tests passing, including a from-scratch `analyze_by_measures` suite the Python test file never covers. See `docs/core/section_analyzer.md`.
- `core/pedal/mod.rs` is a complete, tested port of `core/pedal_generator.py`'s strategy dispatch (`otsu_threshold`, `generate_harmonic_pedal`, `generate_adaptive_pedal_driver`, `generate_ai_pedal`, `generate_events`), 40 tests passing, including two integration tests against the real `resources/pedal_bilstm.safetensors` checkpoint. Model loading/caching (Python's `_weights` cache, `_get_model_path`/frozen-app handling) was deliberately NOT ported into this module -- every function that needs the model takes `Option<&PedalModel>` injected by the caller instead, keeping this module pure and fully unit-testable. See `docs/core/pedal/mod.md`.
- `core/compiler.rs` is now a **complete**, tested port of `core/compiler.py` (all of `compile_note_events`, `compile_midi_pedal_events`, `merge_compiled`, `compile_pedal_events`, `compile_events`), 37 tests passing (29 from the first pass + 8 more once `compile_pedal_events`/`compile_events` were filled in) -- the `todo!()` stubs left after the first pass were filled in once `core::pedal::mod` landed. See `docs/core/compiler.md`.
- Added `use_ai_pedal: bool` (default `true`) to `core::config::PlaybackConfig` while porting `core::pedal::mod` -- it was missing from the initial "consumer key set" pass. See `docs/core/config.md`.
- `core/player.rs` ports `core/player.py`'s decision logic (`PlaybackEngine`) as a pure, clock-injected state machine -- `tick(driver, now) -> TickOutcome` replaces the real `while`/`sleep` cursor loop, and every Qt signal becomes a `PlayerEvent` in the returned list. 40 tests passing. Real background-thread execution and Tauri event dispatch are explicitly NOT part of this module -- see `docs/core/player.md` for the scope boundary and why (`PORTING_PLAN.md` always described this step as two deliverables: this file, plus a Tauri command/event pair that belongs with the `controllers/*` phase). Confirmed via `grep` that `Player.notes`/`Player.tempo_map` are dead fields in the current Python source (assigned, never read) -- neither was ported.
- `managers/config_manager.rs` is a complete, tested port of `managers/ConfigManager.py`, 15 tests passing, using real temp directories (`tempfile` added as a dev-dependency) rather than mocked filesystem I/O. `root_dir`'s PyInstaller-`sys.frozen` detection has no faithful Tauri equivalent and was replaced (not guessed at) with `std::env::current_exe()`'s parent dir unconditionally -- see `docs/managers/config_manager.md`.
- `managers/hotkey_manager.rs` ports `managers/HotkeyManager.py`'s binding/matching decision logic (`HotkeyManager`, `RawKey`, `normalize`) the same way `core/player.rs` ports `Player`'s -- pure, no internal locking -- **plus** the real OS-hook adapter (`rdev_key_to_raw`, mapping `rdev::Key` to `RawKey`; the thread/`AppState`/`app.emit` wiring around it lives in `commands::spawn_hotkey_listener`). 28 tests passing.
